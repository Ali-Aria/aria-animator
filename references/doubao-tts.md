# 豆包语音合成 2.0

## 配置与资源

固定模型名为 `doubao-seed-tts-2-0`，对应官方语音接口资源 `seed-tts-2.0`。使用语音合成 2.0 系统音色，初始化时音色与 API Key 留空。填写入口见 [首次使用](first-use.md)。

配置保存在 `<共享库>/config/tts.json`，模板见 [tts-config.example.json](../assets/tts-config.example.json)。

| 字段 | 初始值 | 说明 |
| --- | --- | --- |
| `model` | `doubao-seed-tts-2-0` | 固定模型名称，由脚本映射成请求头中的资源标识。 |
| `voice_id` | 空字符串 | 用户从官方 2.0 音色列表选取。 |
| `api_key` | 空字符串 | 用户在豆包语音控制台创建的 Key。 |
| `sample_rate` | `24000` | 输出采样率，单位 Hz。 |
| `speech_rate` | `0` | 默认语速，范围为 -50～100。 |
| `loudness_rate` | `0` | 默认音量，范围为 -50～100。 |

脚本不读取外部项目、历史播报记录或全局 `.env`。配音请求固定发送到官方 `openspeech.bytedance.com`，不自动更换服务、音色或模型。

## 合成

合成前按 [口播与预览确认](review-checkpoints.md) 展示完整正文，取得用户对当前版本的确认，或已有明确的跳过口播审核授权。配置齐全不能代替内容确认。画面提示放在稿外。输入采用纯正文，保留段落与自然标点，不使用声音复刻 Expressive 的 Cot 标签。

发音规则位于 `<共享库>/tts/pronunciations.json`，初始内容为 `{"replacements": {}}`。用户可添加专有名词的字面替换。脚本只修改配音副本，保留原文供画面和字幕使用；替换按最长匹配执行，不循环替换。

### 语义分段与停顿

AI 在口播确认后，按完整意思、因果关系、转折和章节安排分段，将计划保存到本片的 `voiceover-segments.json`。尽量让每段说完一个意思，避免把主语与谓语、条件与结论或专有名词拆开。分段保持定稿的字词、标点与顺序，无需单独审核；改写正文仍按口播确认规则处理。

相关短句可放在同一语义段，避免逐句或逐词发起请求，让 TTS 保留段内上下文。短稿可以只用一段；不要为了凑近字符上限，把不连贯的意思合在一起。

计划使用 JSON 数组。下面两段对应的定稿为“先看请求从哪里来。接下来，再看服务器怎样处理。”：

```json
[
  {"text": "先看请求从哪里来。", "pause_after_ms": 200},
  {"text": "接下来，再看服务器怎样处理。"}
]
```

`text` 必填。脚本核对全文覆盖与顺序，只允许省略段间空白，防止漏句、重复或改写。发音替换在各语义段内执行；切断替换词条时会报错，须把完整词条放回同一段。

`pause_after_ms` 可省略，默认 `0`，表示不添加额外静音。它是该段音频之后追加的静音，包含在最终时长中，接受 0～5000 的整数。普通句间停顿交给原文标点与 TTS，只有需要强调、转折或章节转换时才添加。可先尝试 150～350 ms 的短停顿，章节转换可稍长；最终以听检为准，避免与 TTS 自带停顿叠加过长。最后一段通常不追加停顿。

每次请求默认最多 **300 个字符**，按发音替换后的 Python 字符数计，包含标点与空白，不按字节或 token 计。300 是本 Skill 的可调默认值，不代表服务限制或音质保证。超过上限的语义段会继续拆分，计划中的停顿只加在该语义段的最后一个子段之后。

自动拆分优先选取靠近上限的换行、句末、分句标点和空白；没有可用边界时按上限切开。未提供语义计划时，整篇也采用这一规则，不等待服务拒绝长文本。长串无标点正文应优先由 AI 编排合理边界。

### 执行与检查

```text
python "<skill目录>/scripts/synthesize_doubao.py" --input "<项目目录>/voiceover.txt" --output "<项目目录>/public/audio/voiceover.wav" --segments-json "<项目目录>/voiceover-segments.json" --dry-run
```

`--dry-run` 仅检查输入、分段与配置，输出段数、各段字符数和额外停顿，不联网、不创建产物，也不表示用户已经批准口播。检查通过且当前口播已获确认或明确免审后，去掉 `--dry-run` 执行合成。添加 `--max-segment-chars 200` 可将上限改为 200；接受正整数。省略 `--segments-json` 时采用自动拆分。

脚本自动读取已记录成品保存目录下的 `_shared`。兼容独立共享库时，添加 `--shared-root "<共享库目录>"`，或使用同一个环境变量。各段按顺序请求，统一使用本次读取的声音、语速、音量和采样率，不自动重试。

采用官方 HTTP SSE 接口，逐段验证完成标记后保存 16 位单声道 WAV，再按 PCM 采样拼接。默认不裁剪 TTS 自带停顿、不变速、不交叉淡化，只按计划追加静音。单段与多段使用相同输出布局：

| 路径，以 `voiceover.wav` 为例 | 内容 |
| --- | --- |
| `voiceover.wav` | 所有请求成功后生成的完整配音，含明确指定的额外停顿。 |
| `voiceover.txt`、`voiceover.tts.txt` | 定稿原文与发音替换后的全文。 |
| `voiceover.json` | 实测总时长、请求数、非敏感参数及 `segments` 时间清单。 |
| `voiceover.segments/0001.wav` | 各段原始音频，编号从 `0001` 开始，不含脚本追加的静音。 |
| `voiceover.segments/0001.json`、`0001.tts.txt` | 对应段的事件、实测时间、额外停顿与实际提交文本。 |

中途失败时立即停止后续请求，报告失败段号与保存位置，保留已完成分段；不保存失败段音频，也不生成完整 WAV 或总记录。脚本不自动续传。后续可人工复用已完成分段；重新执行整篇会重新请求各段。输出、同名记录或分段目录已存在时停止，重做配音使用新文件名，避免覆盖已有结果。

## 校准与交付

服务返回的时间事件应对照最终音频检查。没有词级时间时，不得用句级时间或字数估计冒充词级时间。发音替换可能让返回文字与字幕原文不同，须建立对应关系。

总记录的 `segments` 包含各段相对音频路径、`start_sample`、`end_sample`、`start_seconds`、`end_seconds`、`duration_seconds` 和 `pause_samples`。起止位置由返回 PCM 的实际采样数计算，末尾位置不含该段追加静音；下一段起点包含此前所有音频和追加静音。最终总时长包含全部追加静音。

各段的 `events` 保留服务原始数据，`event_time_basis` 为 `segment_local`。制作全片字幕时，先核对服务字段与时间单位，再加该段 `start_seconds` 换算为全片时间；不能直接串接局部时间。多段时顶层 `events` 为空，使用 `segments` 中的事件；单段保留顶层事件兼容原用法。

默认不做额外变速或母带处理。用户要求后期音频处理时，保留原始音频、记录参数，并重新校准最终音频与字幕。听检开头、专有名词、各段衔接、停顿长短、音色与语气连续性以及最后一个音节；有问题时调整边界或停顿并重做对应配音与时间校准。

Key 只保存在共享配置中，不进入项目素材、日志或交付包。初始化检查只验证格式；空 Key 和空音色不能发起合成，也不能标记为服务验证通过。

协议依据：[HTTP Chunked / SSE 单向流式 V3](https://www.volcengine.com/docs/6561/1598757)、[API Key 使用说明](https://docs.volcengine.com/docs/DoubaoVoice/APIKeyUsage?lang=zh)。
