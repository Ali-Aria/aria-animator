# 口播与画面信息分工

配音前按观众的理解步骤分配信息。每段先确定观众要理解的变化或判断，再决定哪些要讲、哪些只展示、哪些共同强调。新写稿从这一步开始；已有定稿或成品配音时，在原有语义和时长内安排视觉补充。

## 决定由谁承载

| 承载方式 | 适合的信息 | 决策依据 |
| --- | --- | --- |
| 口播 | 因果、判断、转折、结论成立的条件 | 观众只听声音仍能跟住主线，知道为什么发生和意味着什么 |
| 画面 | 名称、位置、数值、单位、结构、前后对照、具体操作和反馈 | 观众能在当前尺寸和时间内直接辨认，声音可继续解释同一件事 |
| 口播与画面共同强调 | 核心结论、易误解的比较关系、关键边界或安全条件 | 重复能防止误解，画面同时提供关系、过程或证据 |

以实际理解任务判断，不按词性机械分配。决定结论是否成立的数字或条件，要在口播中讲清意义；精确值可由画面保留。长名称可在画面完整展示，口播使用可对应的简称。

只在画面出现的信息须来自用户材料、已核实来源或明确标注的示例。单位、时间范围、版本和比较基准与对应数据一起出现。示意图不能暗示未经证实的比例、时序或因果。来源核对沿用主流程，不因移出口播而省略。

先用动作、位置、形状和状态表达变化，必要时添加最短标签。能够直接演示的过程，优先展示输入、变化与结果。用大段文字替代旁白会增加阅读负担，需改成分步呈现或保留必要口播。

## 在写稿和合成前使用

先保留口播的对象、因果和判断，再把可视细节分配给画面。重读精简后的稿子，检查代词是否仍有指向，结论是否仍有条件，是否出现依赖观众同时读另一段长文才能听懂的句子。不要求纯音频包含全部视觉细节。

使用口播写作技能时，说明这是有画面承接的视频，把信息分工一并传入。配音输入只保留要念出的正文。画面标签、来源和动作提示留在计划中。

用户提供定稿或成品音频时，补充相关的可视信息、关系和证据。任务未包含改稿时，保留原口播。不要为表现分工而强行删句，也不设置“画面专属信息占比”。短片或事实简单的段落，可以没有只在画面出现的信息。

以下均为说明分工的虚构示例，数值与路径不能直接作为真实产品事实使用。

| 原本可能全部念出的内容 | 口播安排 | 画面安排 |
| --- | --- | --- |
| 操作依次进入设置、导出，选择 PNG，再点击保存 | “选好导出格式，再保存。” | 依次打开真实位置，选中 PNG，展示保存反馈；界面标签按需保留 |
| 同一测试从 120 ms 降到 40 ms | “在同一测试条件下，等待时间缩短了三分之二。” | 共用标尺展示前后值、单位和测试条件；变化完成后停住比较 |
| 输入依次经过校验、排队、执行，再返回结果 | “请求通过校验后，先等待调度，再执行。” | 持续主体经过对应节点，标签说明各站，执行后返回结果；口播解释需要展开的等待原因 |
| 某限制仅对指定版本生效 | 讲清“这个限制只针对指定版本”及必要的版本边界 | 对应界面或比较对象旁保留准确版本号，避免把限制画成全版本适用 |

以上口播可随上下文调整。教程以复现操作为目的时，要让步骤和选项足够明确；关键操作或边界仍可共同强调。

## 安排注意力和阅读时间

口播解释与当前画面相关的原因或意义时，可让画面展示对应细节。观众需要阅读密集界面、精确数据或代码时，减少同时出现的新口播信息。用已介绍内容的短句、自然停顿或分步揭示安排观察，不让多个陌生信息同时争夺注意力。

每次只引导一个主要阅读任务。顺序可以是建立对象、展示变化、观察结果、解释含义；按内容调整，不强制每段采用同一顺序。必要的标签靠近主体，关键数值落稳后再引入下一组。

阅读窗口从信息完整、位置稳定且清楚可辨时开始，到信息离开、被遮挡或下一个主要阅读任务接管时结束。入场、滚动、镜头移动和数值插值另计。不要用整段口播长度代替实际可读时间，也不要依赖逐字口播为未被念出的信息计时。

规划时按文字长度、陌生程度、比较任务和输出尺寸估计，再用实际预览校准，不设统一停留秒数。静止读图有明确任务时成立，遵循动作编排的观察区间规则。

阅读时间不足时，先简化、拆开揭示、保留共同参照或调整画面出现顺序。已有配音先在原片长内处理，不压缩到无法辨认，也不用无关动作填空。需要改稿或增加有语义作用的停顿时，按主文件的授权范围和配音重做条件执行。

## 写入现有计划

规划阶段可用简表记录“本段目标、口播、仅画面信息、共同强调、依据和观察任务”，时间未测量时标为暂定。不要把尚未实现的画面承接当作已完成。

制作时沿用 `src/data/choreography-plan.json`，新增或重做的段落添加 `informationDesign`，保留原字段。每段记录口播任务、只在画面出现的信息及其依据、呈现方式、语义锚点和阅读窗口。需要共同强调时简记原因；没有时使用空列表。已在计划中保存的来源和时间点可直接引用。

下面是合并到现有计划的结构示例。`beatId` 和 `eventId` 引用项目中真实的段落和动作事件；示例的空阅读窗口须在正式制作前用实测音频时间补齐。

```json
{
  "informationDesign": [
    {
      "beatId": "export-format",
      "goal": "观众能选择导出格式并识别保存成功",
      "voiceTask": "交代选择格式后保存，避免逐项朗读界面标签",
      "visualOnly": [
        {
          "id": "selected-format",
          "information": "导出格式为 PNG，保存后显示成功反馈",
          "source": "项目内已核实的界面素材或行为记录",
          "presentation": "展示选中态、保存操作和真实结果反馈",
          "anchor": "选好导出格式，再保存。",
          "eventId": "export-save-feedback",
          "readingWindow": null
        }
      ],
      "shared": [],
      "timeBasis": "provisional"
    }
  ]
}
```

正式计划将 `timeBasis` 改为 `measured-audio`，把 `readingWindow` 填为全局整数帧对象 `{"startFrame": 0, "endFrame": 1}`，采用左闭右开区间，并替换为项目真实帧值。窗口须在本次展示区间内且结束晚于开始。前后数值需要分别观察时，拆成不同信息项或记录各自窗口。

`anchor` 可以指向相关句子、句子标识或已核实的语义区间，不要求信息在配音中逐字出现。视觉动作接入现有事件与渲染组件；只填计划不能证明信息已展示。后期只改视觉时，复用已有音频与实测时间。

## 验收信息是否被接住

按正常速度同时听看，核对删出口播的信息是否都能从画面中取得。关闭口播字幕再看，检查名称、数值、关系和操作反馈是否清楚。只听配音时，检查主线、指代和必要条件，不要求复述全部视觉细节。

口播字幕只包含实际念出的内容。视觉标签单独管理，不能写进逐字字幕来伪造承接；字幕关闭时也须保留必要标签。核心结论允许有目的地重复，其他新增文字遵循视觉设计的用途与位置规则。

把观察的片段、信息项、阅读窗口、实际播放尺寸和问题记录到 `qc/workflow-evidence.json`。修复沿用 `qc/production-learning.json`。静态脚本只能检查结构；能否看懂、是否来得及阅读以及声音和画面是否争夺注意力，必须检查实际预览。未完成的播放或听检如实记录。
