# 动作编排

## 先设计接续，再写入场

先按 [场景组织](scene-organization.md) 确定连续片段及跨段镜头，再安排局部动作。
每段记录输入、主体、动作、反馈、结果、关注点和接续对象。进入、活动、退出和接续区间分别指定负责主体；独立主体可以交叠。

沿用 `src/data/choreography-plan.json`。例如：

```json
{
  "id": "rectification",
  "startFrame": 360,
  "endFrame": 540,
  "actor": "alternating current",
  "input": "negative half-cycle enters the bridge",
  "action": "the alternate diode pair conducts",
  "result": "the output half-cycle points upward",
  "focus": "the conducting path",
  "handoff": "the pulse enters the capacitor",
  "camera": {
    "mode": "follow",
    "anchor": "current path",
    "start": "bridge in context",
    "end": "bridge and capacitor together",
    "reason": "show where the pulse goes"
  }
}
```

## 给镜头明确的任务

| 任务 | 适用情况 |
| --- | --- |
| 停住 | 主体自身的动作已能说明关系 |
| 跟随 | 需要看清传递、操作或移动的目的地 |
| 改构图 | 结果引出新的关系、尺度或环节 |
| 切镜头 | 主题改变，或移动会错误暗示连续关系 |

记录关注点、起止构图、运动区间和持续可识别的主体。共享空间使用世界坐标。
前后层次须有解释作用，避免镜头与多个无关前景动作争夺注意力。
镜头落点须可读。快速移动可使用方向模糊，但主体和结果仍须可识别。

普通平移、缩放入场和退场约用 0.25 秒～0.6 秒；较大的镜头重构图约在 0.8 秒内完成。
落稳后留出阅读时间，不按整段口播长度拉长补间。较长跟随只用于确需追踪的可见传递或过程。
路径传递、变形、数值插值、遮罩揭示、错峰装配、图形描绘、粒子流和界面操作按解释需要选用。

## 区分主动作和次级动作

主动作改变状态、传递主体或揭示关系。次级动作表达碰撞、惯性、重量或气氛，例如震动、回弹和轻微镜头漂移。
使用次级动作时，记录目的、触发或情境、活动区间、强度和结束方式。冲击响应逐渐衰减，气氛动作平缓进入和退出。

同一属性在一个控制器内合成主姿态和次级偏移。偏移按固定种子和帧时间计算，用区间包络控制强度，区间外归零。
有阅读任务的观察期可保留克制的次级动作；声明静止的区间须冻结全部状态。

无目的的晃动、往返和每段照搬的漂浮循环须删除。真正作为讲解对象的振动、旋转或周期传输可以重复。
次级动作不能充当等待主要事件时的有效进展。

## 安排时间

### 先动作，后语音时间点

先设计内容支持的输入、变化、反馈、结果和接续，再使用核实的语音时间点安排预备、开始、强调和结果。
规划阶段可用明确标记的暂定时间；正式配音制作使用实测成品音频。
不按每个名词套用效果，不为填时间编造步骤、结论或进度。

| 时间区间 | 含义 |
| --- | --- |
| 解释区间 | 口播展开这一结论或相关结论的时长 |
| 动作区间 | 一次移动、揭示或反馈的执行时长 |
| 观察区间 | 结果落稳后，观众检查指定内容的时间 |

分别安排这些区间。错峰装配可以持续较久，每个部件仍保留短动作。
不规定事件数量、等距触发、固定切镜头间隔或静止比例。有一个有效变化时，允许保留可读结果。
停顿缺少观察内容时，重做表现方式或揭示相关关系；保持已确认的文案和事实。

### 检查动作前的等待

动作镜头进入时就开始有意义的准备或动作，可留短暂观察时间。争取在首秒内出现有效进展。
有效进展须改变理解，例如打开相关界面、操作后得到反馈、输入内容、揭示关系或开始有依据的过程。
整套布局淡入、指针晃动、字幕改变或没有揭示内容的镜头移动，不能满足这项要求。

决定性语音时间点较晚时，按内容选择处理方式：

- 提前呈现有依据的准备，让关键变化或结果落在对应时间点。
- 继续展示仍有解释作用的上一段结果，在新动作能开始时切入。
- 拆成有依据的状态，推迟尚无任务的主体出现时间。

自然预备可在强调时间点前约 0.2 秒～0.4 秒开始，前提是当前语境已说明动作含义。
更早的准备须有独立事件和观察目的。保留条件、数值、不确定性和因果顺序，成功结果不能提前出现。
每次主动作仍使用原有时长；调整切镜头后检查相邻两段，避免把等待移到上一段。

例如，验证语句在入场 5 秒后出现时，可以先展示已介绍的接口差异，再按时间点验证。
内容不支持提前动作时，保留有用证据，靠近验证事件再切入。不能添加虚构连接或进度条。

入场后超过 1 秒才有有效进展，或约 2 秒以上没有变化，须复查。阈值只用于定位问题，动作数量由内容决定。
截图、公式、密集界面、必要对比和结尾结果可静止，须记录观众要看的内容。
用渲染帧核实首次有效变化和停顿用途，不能只看事件名称或声明的进入区间。

### 可选事件字段

现有段落可添加 `events`，保留原字段：

```ts
type MotionEvent = {
  cueId: string;             // 核实的语音时间点；规划时可标为暂定。
  actor: string;             // 已有语义主体的身份。
  action: string;            // 用普通语言描述可见变化。
  motionType: string;        // 可扩展的动作类型。
  startFrame: number;        // 项目全局时间线上的整数帧。
  durationInFrames: number;  // 正整数，与语音片段时长独立。
  syncRole?: 'onset' | 'emphasis' | 'result';
  cueAnchorFrame?: number;   // 对应语音的全局帧，不一定是 startFrame。
};
```

`startFrame` 表示可见动作的开始，不能默认复制字幕起点。
只在画面出现的信息，使用相关句子或语义区间作时间锚点，不虚构对应的口播关键词。观察区间从内容完整、构图可读时计算，入场和数值变化的时间另计；具体分工见 [口播与画面信息分工](information-design.md)。
语音对应强调或结果时，用 `syncRole` 和 `cueAnchorFrame` 另记该帧，安排短动作使指定时刻一致。
更早的准备独立记录。注明时间来源和精度；句级时间不能称为词级时间。
安排理由写入计划或检查记录，不加到画面。新动作名称仍须遵守同类动作的时长。

按事件结束、下一事件、原有区间和主体控制器推导观察区间。
独立主体可在因果清楚时交叠。同一跨段主体保持一个连续控制器。
全局帧转为所属 `Sequence` 的局部帧只做一次；改变帧率时保持真实秒数。

无需退出动画时，可用 `[boundaryFrame, boundaryFrame]` 表示空退出区间。
注明主体继续存在还是在该边界卸载，无需为了填写字段加淡出。

## 表现交互和接续

界面操作须呈现初始状态、操作、即时反馈、系统响应和落稳结果。指针或焦点按说明需要安排。
使用真实的点击区域、输入节奏、选中状态、加载和确认；保留原有界面标签。只有游标移动而没有产品反馈是不完整的操作。

按质量感和作用区分动作速度。小指示器可快，大面板或组合体可缓慢加速并落稳。
反馈可与原因交叠，但须看得懂。避免所有层同帧启动、使用相同缓动和同帧停止。

| 接续方式 | 画面关系 |
| --- | --- |
| 主体接续 | 同一主体继续、改变作用或进入下一系统 |
| 形状对应 | 形状、路径、数值或遮罩引导注意力 |
| 遮挡或揭示 | 有作用的前景遮住旧状态并显露新状态 |
| 直接切镜头 | 结果完成后进入改变的主题 |
| 交叉淡化 | 确实需要混合状态时使用 |

主体跨段时保留路径方向和表观速度。需要转向时展示转弯，或明确切镜头。
下一主要动作开始前，留出理解结果的时间。
检查出段末帧、边界帧和入段首帧，清理旧文字、面板和效果；避免意外跳变或两套全屏状态竞争。
独立片段切换时，先结束出段的全屏状态，再启用下一段；明确设计的状态混合除外。
最后一个结论落稳后，按主文件的统一显示帧停留规则结束。无新增视觉结论的回顾或行动提示可与停留重叠。

## 动作配置与组合

新制作显式使用 `motionProfile: "process"`。配置影响简单动作的速度、错峰和位移幅度，不改变事实、语音时间或证据阅读要求。开头、章节和关键结论可局部使用 `impact`；用户要求克制时使用 `quiet`。不增加选择风格的审批步骤。
实现和验收按 [process 制作与接入](process-production.md) 执行。`entry`、`stagger` 和 `profile.amplitude` 等返回参数要进入主体控制器。计划中的聚合、拆分和传递须有对应的可见过程。

| 配置 | 入场 | 退出 | 错峰间隔 | 位移倍率 |
| --- | --- | --- | --- | --- |
| quiet | 0.45 秒 | 0.35 秒 | 0.08 秒 | 0.6 |
| process | 0.40 秒 | 0.30 秒 | 0.05 秒 | 1.0 |
| impact | 0.30 秒 | 0.25 秒 | 0.035 秒 | 1.25 |

上述数值可覆写。复杂过程保留自身阶段，不用统一时长压缩全部动作。进入、主动作、观察、退出和错峰分别配置；延长观察时间不拉长动作。独立主体错开开始和落稳时间，用原因、响应和结果建立焦点交接。预备、回弹和交叠按内容选择。

`src/motion/runtime.ts` 提供纯函数；`primitives.tsx` 提供遮罩和真实场景转场。按需复制 `runtime.ts`、`primitives.tsx`、`DynamicShots.tsx` 和所选镜头源码到项目，不依赖安装目录运行。`dispatch.tsx` 接入原 SRT 制作系统；`Fixtures.tsx` 仅用于验证，不是普通项目的必需依赖。

```tsx
<UiAeCardSwarmTimeline
  motionProfile="process"
  timingSeconds={{entry: .4, action: .6, hold: 1.2, stagger: .05,
    phases: {timeline: {start: 3.5, duration: .4}}}}
  brand="工作台" title="输入进入编辑流程" cardLabels={['资料', '任务', '结果']}
/>
```

`timingSeconds` 支持 `entry`、`action`、`hold`、`exit`、`stagger` 和 `phases`。阶段使用 `{start, duration}`，单位为当前组件局部秒数。`timingFrames` 使用相同结构，单位为当前帧率的帧数；`entryFrames`、`exitFrames` 和 `staggerFrames` 优先于同名秒配置。命名阶段的显式帧窗口也优先于秒窗口。空阶段瞬时完成，负数、非有限数和未知 motionProfile 报错。

`exit` 未指定时保留结果。指定后，在组件结尾安排独立退出；可通过 `phases.exit` 提前退出。`hold` 改变下一阶段开始时间，不伸缩已完成动作。跨段持续主体由一个全局控制器管理，不能借局部窗口重新初始化。

复杂阶段名称：卡片群聚使用 `typeBeat`、`swarm`、`grid`、`timeline` 和 `playhead`；产品网格使用 `deck`、`tiles`、`field`、`interfaceIn` 和 `macro`；动势文字使用 `phrase-0` 等；逐项动作使用 `word-0`、`bar-0`、`card-0`、`tile-0` 等。在制作计划的 `events` 中记录对应动作和核实的时间锚点，不改变原有字段。

空间错峰支持 `center`、`edges`、`distance` 和 `path`。输入主体坐标，返回稳定排序；路径模式必须提供完整、不重复的索引顺序。用排序决定时差，保留因果顺序，不随机安排事实结果。

`SceneTransition` 接收 `outgoing` 和 `incoming` 两个真实场景，支持 `wipe`、`slide` 和 `zoom`，可指定方向及转场窗口。遮挡模式在全覆盖时切换底层；方向滑移保持场景相邻；缩放模式仅在运动窗口混合。共享过程继续使用同一世界；转场不替代主体身份与结果接续。

RGB 故障和白闪仅作为可选强调，不纳入默认讲解。
