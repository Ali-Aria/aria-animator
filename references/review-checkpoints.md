# 口播与预览确认

默认按“交付口播稿 → 用户确认 → 合成配音和制作视频 → 完整低清预览 → 用户确认 → 正式画质渲染”执行。两个确认节点独立生效。

## 口播确认后开始制作

将完整口播正文展示给用户，或提供可直接打开的稿件文件，注明版本。必要的事实待核项、发音提示和估计时长放在稿外。明确请用户检查内容，等待确认后再调用真实 TTS、实现本片动画或渲染视频。

等待期间可以核对资料、检查环境和配置、规划口播与画面的信息分工；不能以试合成、试片或后台任务绕过确认。配置填好、检查通过、用户暂未回复，都不代表口播已确认。

用户明确说“这是定稿，直接用”或已在本次会话批准同一版本时，直接复用该确认，不重复询问。仅附上草稿、资料或音频不等于确认；已有音频且用户明确要求原样使用时，视为内容已确认，跳过合成并测量真实时长。明确制作无口播视频时，此节点不适用。

确认后需要改动口播文字或事实表达时，展示新版本并重新确认，再重做配音和相关画面。用户给出具体修改并明确要求改后继续，视为批准该修改范围。发音纠正、音量调整或纯视觉修复不改变口播内容时，复用原稿确认。

## 预览确认后渲染正式版

完成制作和内部检查后，默认交付完整时间线的低清预览。16:9 默认 960×540，其他画幅按比例降低分辨率；保持正式版的帧率、时长、配音、启用的字幕和音效、场景与镜头逻辑。使用 `preview-v01.mp4` 等版本化文件名，提供可播放文件或链接，并说明这是待确认预览。

交付后请用户检查内容、节奏、字幕和声音，等待批准再启动完整画质渲染。内部短片、静帧、联系表、技术测试通过或 Agent 自查不能代替用户确认。不得等待用户回复的同时在后台渲染正式版。

用户提出修改时，完成修改并交付新预览，再等待确认。用户明确说“按这些修改直接导出正式版”时，按该范围继续。仅提高分辨率或编码质量时，复用已批准的预览；改动口播、镜头内容、节奏或声音后，原预览批准不自动适用于新版本。

## 用户明确授权时跳过

授权可以来自本次任务的前文，无需重复确认。只跳过用户授权的节点：

| 用户指令示例 | 执行方式 |
| --- | --- |
| “口播你定，不用给我审核，直接配音制作。” | 跳过口播确认，仍交付低清预览并等待正式渲染批准。 |
| “不用预览，直接渲染正式版。” | 跳过预览确认；口播仍需确认，除非已经批准或另有授权。 |
| “全程不用确认，你直接做成片。” | 两项确认均跳过，仍完成技术与内容自查。 |
| “帮我做个视频”“尽快完成”“导出 1080p。” | 正常执行两项确认，目标格式和进度要求不代表跳过。 |

在现有制作记录中简要注明所用稿件版本、预览版本及对应确认或跳过授权。不要添加额外的风格、模板或音效审批。维护 Skill、检查组件和运行离线测试不属于用户视频制作，无需套用这两个确认节点。
