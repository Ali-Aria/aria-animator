# 界面交互动效

用于软件操作、产品状态变化和生成式 UI。以目标界面的布局、控件、反馈和状态变化为依据，用时间线复现操作过程。

## 确定画面依据

真实产品行为以用户提供或核实的界面、操作顺序和文案为依据。截图和录屏截帧可用于重绘参考；直接展示时，遵守 [视觉设计](code-motion-design.md) 的证据图片规则。

用 React 和 SVG 重绘时，复现几何、字体、间距、色彩、控件和关键状态。保留关键标签、数据和空间关系；真实界面无法确认时，标明示意。
从证据转入示意时，先展示原界面，再明确抽取控件或流程，让观众看清两者关系。

## 安排操作和反馈

每个关键操作写清：起始状态 → 触发 → 即时反馈 → 处理中间态（若存在）→ 结果 → 下一步。
记录各状态对应的配音时间。按钮、焦点、输入、加载、成功或错误须有解释用途，异步结果须有系统响应。

一个主要动作承载一项信息。界面原生文字证明功能，旁白和字幕负责解释；新增标签只补充界面无法说明的事实。
内容密集时移动焦点、调整构图或分阶段揭示。鼠标移动和打字按说明需要安排。

## 布局和接续

按任务分配命令区、工作区、检查器和结果区。相同对象跨状态保留身份、位置线索和层级，结果可成为下一镜头的关注点。
桌面和竖屏分别安排布局，重排区域并保留操作关系。桌面截图缩小不能代替移动布局，元素须避开关键文本、控件和证据。

指针和焦点只说明目标与因果。点击前目标可辨，点击后有即时反馈；选中、拖拽和输入须改变对应状态。

## 实现与复查

用事件帧和可编辑状态数据驱动控件，按主文件的帧驱动规则重建任意帧。
直接展示的截图在阅读期间保持完整、固定，强调层独立绘制。默认按视觉设计规则添加短暂进出场，图片与强调层同步运动，落稳后固定。用户要求静态展示时关闭进出场。

对照来源检查起始、反馈、中间、结果和接续状态。核实布局、文案、操作目标和响应时间，真实错误不能呈现为成功。
检查横竖屏的字号、遮挡和安全区，静帧与连续动作按 [制作检查](production-and-qc.md) 复查。
