# 首次使用引导

## 识别 Python 命令

先检查 `python --version`。命令不存在或版本低于 3.10 时，检查 `python3 --version`；Windows 还可以检查 `py -3 --version`。使用第一个满足要求的解释器。命令打开应用商店或没有返回 Python 版本时，继续检查下一个候选。

本 Skill 文档中的 `python` 均指这一步确认的命令。只有 `python3` 时替换为 `python3`，使用 Windows 启动器时替换为 `py -3`。初始化、配音和检查沿用同一解释器，避免混用虚拟环境。自定义可执行文件路径含空格时，按当前 shell 引用；PowerShell 调用带引号的路径时，在前面加 `&`。

镜头库的 `npm run render:previews` 和 `npm run validate:shots` 会自动检测上述命令并检查版本。需要指定解释器时，将环境变量 `ARIA_ANIMATOR_PYTHON` 设为可执行文件路径，兼容旧版 `MOTION_EXPLAINER_PYTHON`；两者都设置时使用新名称。变量值不加额外引号或命令参数，不能填成 `py -3`。显式配置无效时会报错，不切换到其他环境。直接运行 Python 脚本时，仍使用已确认的解释器命令。

## 引导选择成品保存目录

首次初始化前，先告诉用户：共享库和视频项目放在同一个保存目录中，共享库名为 `_shared`，每个视频单独建文件夹，与 `_shared` 并列。解释两者的用途，再询问成品保存位置。

| 目录 | 保存内容 |
| --- | --- |
| `<成品保存目录>/_shared` | 跨项目复用的配音配置（音色 ID、API Key 和音频参数）、发音规则、字体及许可证、缓存。升级 Skill 时保留。 |
| `<成品保存目录>/<视频名称>` | 该视频的口播稿、可编辑源码、素材、配音、字幕、预览、正式成片和检查记录。每个视频独立保存。 |
| Skill 安装目录 | 制作规则、脚本和内置镜头库，由 AI 宿主管理。 |

可以这样问：

> 你希望把成品保存在哪个目录？共享库也会放在这个目录的 `_shared` 文件夹里，用来保存配音配置、发音规则、字体和缓存。每个视频会有独立文件夹，保存成片、源码、素材和检查记录，并与 `_shared` 并列。请告诉我保存目录的完整路径。

可按用户的系统给出一个具体建议路径，但等待用户选择后再初始化。不要未经选择就在用户主目录创建共享库。用户已在本次会话给出位置，或本机已保存同一选择时，直接复用，不重复询问。用户只安装、暂不选择时，报告“Skill 文件已安装，保存目录待选择”，不下载字体、不创建共享配置。

复用时检查用户主目录下 `.aria-animator/locations.json` 的目录记录；新记录不存在时，复用旧版 `.motion-explainer-studio/locations.json`。检查已设置的 `ARIA_ANIMATOR_SHARED`，兼容旧版 `MOTION_EXPLAINER_SHARED`。旧版共享库可能位于 `.motion-explainer-studio/shared`，另有自定义位置时沿用已知记录，不搜索其他项目的凭证。旧布局要调整为并列结构时，先说明现有位置并让用户选择保留或迁移；不自动搬动、删除或另建一套空配置。

## 初始化并展示实际位置

用户选好后，用已确认的 Python 命令运行下列脚本。宿主没有安装后钩子时，由 Agent 在首次调用 Skill 时执行。`<skill目录>` 必须解析为当前 `SKILL.md` 所在目录；保存目录必须替换为用户选择的绝对路径。

```text
python "<skill目录>/scripts/setup.py" --workspace-root "<用户选择的成品保存目录>" --install-fonts
```

Python 需要 3.10 或以上版本。初始化和配音脚本只使用标准库。初始化只创建 `_shared` 及目录记录，不创建视频项目，不调用配音服务，也不覆盖已有配音配置。

新安装把保存目录记录到用户主目录下的 `.aria-animator/locations.json`，其中只有目录路径。已有旧版记录且尚无新记录时，继续读写旧文件，实际位置以脚本输出为准。API Key 留在用户所选目录的 `_shared/config/tts.json` 中。后续初始化和配音脚本自动沿用记录中的 `_shared`；项目素材和音效仍按本片项目目录归档。

将脚本返回的真实绝对路径整理成简短说明，明确展示：

| 位置 | 作用 |
| --- | --- |
| `workspace_root` | 用户选择的成品保存目录，容纳 `_shared` 和各视频文件夹。旧版独立共享库模式下为空，不能虚构成品位置。 |
| `skill_path` | 存放制作规则、脚本和镜头库。 |
| `shared_library_path` | 跨项目保存个人配音配置、发音规则、字体与缓存。升级 Skill 时保留此目录。 |
| `tts_config_path` | 用户自行填写音色 ID 和 API Key 的配置文件。 |
| `font_path` | 从 GitHub 下载的霞鹜文楷字体及许可证。 |
| `locations_config_path` | 保存所选目录的本机记录文件，不含配音凭证。 |

完整绝对路径须以可见文本展示，可同时附可点击链接。不要只显示“共享库”等链接标题，让用户无法直接看到实际位置。未创建的目录标为计划位置。

`--shared-root` 和共享库环境变量用于已有独立共享库，优先于已保存的目录记录。环境变量优先读取 `ARIA_ANIMATOR_SHARED`，未设置时读取旧版 `MOTION_EXPLAINER_SHARED`。首次采用并列结构时使用 `--workspace-root`，不同时传入 `--shared-root`；生效的环境变量指向其他位置时先处理冲突。切换目录不会迁移旧配置，迁移需求须单独处理。

## 引导填写配音配置

向用户展示以下链接与配置文件的实际路径，让用户在本机编辑文件：

- [豆包语音控制台](https://console.volcengine.com/speech)：开通语音合成 2.0 服务。
- [API Key 管理](https://console.volcengine.com/speech/new/setting/apikeys?projectName=default)：创建豆包语音 API Key。
- [官方音色列表](https://www.volcengine.com/docs/6561/1257544)：在“豆包语音合成模型 2.0”列表中选择音色，复制对应 ID。
- [API Key 使用说明](https://docs.volcengine.com/docs/DoubaoVoice/APIKeyUsage?lang=zh)。

配置模板中的 `voice_id` 和 `api_key` 均为空。`model` 固定为 `doubao-seed-tts-2-0`，其他音频参数已有初始值。说明这里需要系统音色，声音复刻 2.0 的克隆音色属于另一类资源；方舟文本模型的 Key 也不能直接当作豆包语音 Key。

用户填写后运行 `setup.py`，检查字段格式并再次展示 `tts_config_path`。报告“配置已保存在此处”，仅说明 Key 是否已填，不回显文件全文。字段齐全表示本地配置完成，服务权限与音色可用性仍需首次真实合成验证。

Key 留空时，可以继续口播和画面规划。合成需要等待用户填好，并遵循 [口播与预览确认](review-checkpoints.md)，先确认口播内容。用户明确要求原样使用成品配音时，跳过合成。不要从其他项目、环境文件或历史输出中查找用户的声音和密钥。

## 首次项目检查

用户开始制作视频时，在所选保存目录下为本片建立独立子目录，例如 `dns-explainer-20261020`，并展示实际绝对路径。名称冲突时另取名称，修改已有视频时复用原项目。若此前暂未选择成品保存目录，此时完成上面的引导；不得把当前 Skill 仓库当作视频项目。

默认目录结构如下，已有项目沿用原布局并说明实际位置：

```text
<成品保存目录>/
├── _shared/
└── <视频名称>/
    ├── voiceover.txt
    ├── src/
    ├── public/
    │   ├── audio/
    │   ├── images/
    │   └── fonts/
    ├── previews/
    ├── renders/
    └── qc/
```

`src/` 保存可编辑源码与制作计划；`public/` 保存项目使用的音频、图片、字体和字幕等素材。`previews/preview-v01.mp4` 保存完整低清预览，`renders/final-v01.mp4` 保存正式成片；导出的独立音效轨也放在 `renders/`。`qc/` 保存联系表、检查证据和修复记录。

安装阶段只记录保存位置，具体视频目录和文件在对应制作阶段创建。交付时展示项目目录、预览和成片的实际绝对路径，提供可播放文件或链接；尚未导出的正式版不能写成已存在。

按 [共享库与项目依赖](shared-dependencies.md) 准备 Node.js、项目依赖、浏览器和媒体工具，再按 [字体接入](fonts.md) 把共享字体复制到项目。

后续调用复用已有配置。若文件缺失、字段为空或用户要求更换配置，再展示对应设置步骤；不要每次都让用户重填。
